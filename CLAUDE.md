# Repository conventions (must follow)

This repo holds the mobile + Wear session-viewer clients split out of
[`yschimke/compose-ai-tools`](https://github.com/yschimke/compose-ai-tools) (see
[#2533](https://github.com/yschimke/compose-ai-tools/issues/2533)). It inherits
that repo's house conventions:

## Git

- **Git history must never attribute work to an AI agent.** No `Co-authored-by:`
  trailer naming an agent (Claude / Codex / ChatGPT / Copilot / Gemini) or using
  an agent email, and never an author/committer identity that is an agent. Session
  links (`claude.ai/code`) and the "🤖 Generated with …" / `_Generated by [Claude
  Code]_` footers are fine. Enforced by `.githooks/commit-msg` (install via
  `scripts/install-git-hooks.sh`).
- **Branch names are always `agent/…`**, never `claude/…` / `codex/…` / any other
  agent prefix.
- **Conventional Commits** for PR titles and commit subjects (`fix:`, `feat:`,
  `docs:`, `test:`, …) so squash merges feed release-please.
- **Re-check PR state immediately before every push.** If the PR has already
  merged, branch fresh from `origin/main` for the follow-up.

## Build

- Kotlin is formatted with **ktfmt (googleStyle)** — `./gradlew ktfmtFormatAll`.
  The `pre-commit` hook gates this.
- `:core` is pure-JVM and unit-tested headlessly (`./gradlew :core:test`).
- `:mobile` / `:wear` need an Android SDK to assemble/lint.

## The wire contract

`:core` re-implements the `compose-preview serve` wire protocol against the
[versioned spec](https://github.com/yschimke/compose-ai-tools/blob/main/docs/serve/SESSION-VIEWER-PROTOCOL.md)
owned by `compose-ai-tools`. It is a **wire** dependency, not a code dependency —
never add a Maven/project dependency on `compose-ai-tools` internals. If the
contract needs to change, change the spec there first.

## Publishing

The apps publish to Google Play's internal track via Gradle Play Publisher, driven
by release-please + `.github/workflows/release.yml`. See
[docs/PUBLISHING.md](docs/PUBLISHING.md).
